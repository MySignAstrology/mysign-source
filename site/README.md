# site/ — the public website (mysignapp.com/)

The landing page people reach from TikTok, a shared link or a search. Plain
HTML, CSS and a little JavaScript. No framework, no build step, no third-party
scripts. The web app itself lives at `/app`.

| File | What it is |
|---|---|
| `index.html` | The page: hero, how it works, accuracy, people, memory, privacy, FAQ, final CTA, and the **start sheet** (`<dialog id="start">`). Layout CSS is inline because only this page uses it. |
| `ig.html` | The Instagram bio-link page at `/ig`. It tags the visit `utm_source=instagram` before `track.js` runs, so a bare link is still counted, and the tags reach `/app` after sign-in. Not indexed. |
| `gifts/` | The zodiac gift guide at `/gifts` and `/gifts/<sign>`. Generated by `tools/gift_guide.py` from `shop-catalog.js`; don't edit by hand. Indexed. |
| `check.html` | The public compatibility check at `/check`: two birthdays, one score, no account (`POST /api/vs`). Indexed. Its sign-up carries their birthday to People through sessionStorage `ms_check`. |
| `brand.css` | The shared design language: tokens first (light, then dark through `prefers-color-scheme`, the same way the app switches), then sky/grain, type, fields, buttons, glass cards, sheet and orbit. Copied faithfully from `app/static/index.html` so the app can later `@import`/`<link>` this same file. |
| `sky.js` | `MySky`, copied verbatim from the app: the background follows the real local time of day. It runs synchronously in `<head>` so the first paint is already the right sky. |
| `site.js` | Header frost, reveal-on-scroll, invite banner, and the start sheet (sign in / sign up). |
| `track.js` | First-party, privacy-first analytics (`window.MsTrack`), described below. |
| `og.png` / `og.html` | 1200×630 share image and its source. `og.html` is not linked from anywhere. |
| `robots.txt`, `sitemap.xml` | Crawl rules (Disallow `/app`, `/api/`, `/ops`, `/bt/`) and the four public URLs. |
| `serve.py` | Local dev server and proxy (stdlib only). |

## Run it locally

```sh
MYSIGN_DEV_AUTH=1 ./run.sh          # site at http://localhost:8420/, app at /app
python site/serve.py                # the site alone, http://localhost:8430
```

`./run.sh` is enough on its own: `app/server.py` serves this folder at `/` the
way the edge does (see "Routing the edge must do"). `serve.py` is for editing the
site without restarting the app.

`serve.py` serves the files in this folder at `/` and proxies everything the app
owns to `--upstream` (default `http://127.0.0.1:8420`): `/api/*`, `/app*`,
`/static/*`, `/privacy`, `/terms`, `/accuracy`, `/e`, `/ops*`, `/bt*`,
`/manifest.webmanifest`, `/sw.js`, `/favicon.ico`. That is how the edge is meant
to split traffic in production. Cookies, status codes and streamed responses
pass through unchanged. Flags: `--port`, `--host`, `--upstream`.

With `MYSIGN_DEV_AUTH=1`, no email is sent. The code comes back in the
response, and the sheet shows it in `#devCode`, the same way the app does. The
banner appears only when the server includes `dev_code`.

### Routing the edge must do

The site's files are served flat from the root: `/`, `/brand.css`, `/sky.js`,
`/site.js`, `/track.js`, `/og.png`, `/robots.txt`, `/sitemap.xml`. Everything
else listed above goes to the app. A visitor who already has a session, or who
arrives on an app link (`?invite=`, `?p=`, `?sky=`), is redirected from `/` to
`/app` with the query kept, by `deploy/edge/router.js` and, with Lambda serving
`/`, by `app/server.py`. The page itself does not check.

## Contracts with the app and other agents

### `GET /api/auth/channels`
Returns `{"email": true, "sms": true|false}`. The sheet asks once, about a
second after load and again when it opens, with a 4-second timeout. **If the
call fails or 404s, the sheet assumes email only**: the field is labelled
"Email" and digits get a "use your email" hint. Today's server has no such
route, so email-only is what you see.

### `POST /api/auth/request`
Body: `{"email": "a@b.co"}` **or** `{"phone": "+15551234567"}` (E.164, US only
for now), plus an optional `"anon_id"` (see below).

Input detection: anything containing `@` is treated as an email. Otherwise
digits are read as a US phone number, shown as `(555) 123-4567`, sent as
`+1…`. Phone input is only accepted when `channels.sms` is true.

Success returns `{"sent": true, "channel": "email"|"sms"}`. Today's email path
returns `{"sent": true}`, and dev mode returns `{"sent": false, "dev_code": "123456"}`;
all three work. Errors are non-2xx with FastAPI's `{"detail": "..."}`, and the
string is shown verbatim in the sheet's `role="alert"` line. Keep `detail`
messages human.

### `POST /api/auth/verify`
Body: the same identifier key as the request, plus `"code": "123456"` and
optionally `anon_id`. Sent with `credentials: 'same-origin'`; the server sets
the session cookie. On 2xx the page calls
`location.assign('/app' + location.search)`, so `?invite=…` and `utm_*` reach
the app.

### `anon_id` in auth bodies
The auth bodies carry an optional `anon_id`, a 26-character Crockford base32
ULID from `localStorage.ms_anon`. The current pydantic models ignore unknown
fields; `tests/test_site.py` holds that in place. If a model ever moves to
`extra="forbid"`, add the field or the site's sign-in breaks. The point is to
let the collector join the anonymous site visit to the account it became.
`anon_id` is omitted when the visitor sends Global Privacy Control or DNT.

### `sessionStorage.ms_code_for`
While a code is pending, the site stores **JSON**
`{"kind": "email"|"phone", "value": "<email or +1E.164>"}` under
`ms_code_for`, and clears it after a successful verify or "use a different
email". Both `/` and `/app` write this shape and read it to resume the code step after
a refresh or when the user switches to their mail app. Both readers also accept
what the app wrote before the move, `{"id": ..., "kind": ...}`, and a bare
email string, so in-flight sessions survive the deploy.

### `POST /e` (analytics collector)
`track.js` sends batches with `navigator.sendBeacon`, falling back to
`fetch(..., {keepalive: true})`:

```json
{"events": [{
  "event_id": "01JAX…(ULID)", "ts": 1730000000000, "source": "site",
  "anon_id": "01JAW…" , "session_id": "01JAX…",
  "type": "page" | "tap",
  "name": "home" | "start_open" | "section_view:how" | "start_code_sent" | …,
  "screen": "home", "props": {},
  "ctx": {"utm_source": "tiktok", "utm_medium": null, "utm_campaign": null,
          "referrer_domain": "tiktok.com", "landing_path": "/"}
}]}
```

- `ts` is epoch milliseconds. Names match `^[a-z0-9][a-z0-9_.:-]{0,59}$`, and anything else is dropped client-side.
- Events sent:
  - `page` `home` on load.
  - `tap` for every `[data-track]`: `start_open`, `signin_open`, `start_submit`, `code_submit`, `how_open`, `accuracy_open`, `privacy_open`, `faq_open:<slug>`.
  - `tap` `section_view:<slug>`, once per section, through IntersectionObserver.
  - `tap` `start_code_sent` / `start_verified` with `props: {"channel": "email"|"sms"}`. The server's `auth.code_requested` / `auth.verified` events are the authoritative counts; these only mark the step in the site session.
- `anon_id` lives in `localStorage.ms_anon`. `session_id` lives in `sessionStorage.ms_sess` and rolls over after 30 idle minutes. First-touch UTM is kept in `localStorage.ms_utm`. Only the referrer's **domain** is sent.
- With `navigator.globalPrivacyControl` or DNT, nothing is written to storage and `anon_id`/`session_id` are `null`.
- Flushes happen every 10 s, at 20 queued events, and on `visibilitychange: hidden` / `pagehide`. A 404 (collector not deployed) fails silently.

## The app move

- `manifest.webmanifest` has `start_url: "/app"` and `id: "/"` (the identity
  existing installs already have). The site does not link the manifest;
  installing is an app concern.
- `sw.js` stays registered with scope `/`, because push subscriptions belong to
  that registration. It controls this page too, but only network-first: offline
  it serves the site's own last copy or nothing, never the app's shell.
- After sign-out a browser tab is sent here, to `/`; an installed app stays on
  its own sign-in screen at `/app`.
- The privacy policy does not mention the site's anonymous analytics yet
  (`anon_id`, UTM, referrer domain). Add a line when `/e` ships.

## Share image

`og.png` is `og.html` rendered by headless Chromium at 1200×630:

```js
// node, with @playwright/test installed (npm ci)
const { chromium } = require('playwright');
(async () => {
  const b = await chromium.launch(), p = await b.newPage({ viewport: { width: 1200, height: 630 } });
  await p.goto('file://' + require('path').resolve('site/og.html'));
  await p.evaluate(() => document.fonts.ready);
  await p.screenshot({ path: 'site/og.png' }); await b.close();
})();
```

## Tests

- `tests/test_site.py` covers markup, meta and SEO, links that resolve, no
  external scripts, the ids the scripts need, analytics names, robots and
  sitemap, the share image size, `serve.py` routing, and the auth endpoints
  accepting `anon_id`.
- `tests/e2e/site.spec.js` starts its own app and `serve.py` on spare ports.
  It goes through the whole start sheet: email, dev code, verify, cookie set,
  redirect to `/app`. It also checks the `/e` payload, the sign-in mode, and
  axe accessibility.
  Run it alone with `npx playwright test -c tests/e2e/site.config.js`. It is
  also picked up by the default config.
